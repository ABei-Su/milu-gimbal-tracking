# 识别连续性优化与补充事项

2026-09-22，原版0.4.0；测温集成版0.3.0复用同一套milu核心，D55驱动与眼周MixFormerV2保持。

## 已修改

- 模型推理输出置信度最低0.4的候选；新目标仍需confidence=0.65。屏幕分别显示强目标数量和候选数量，避免把弱候选当成稳定识别。
- 已有目标仅在框重叠IoU>=0.3、面积比0.5..2、原关联半径内且候选唯一时允许弱检测延续。自上次强检测最多持续stale_after=0.25秒。
- 弱检测不启动新目标、不自动切换新目标、不允许激光点亮；激光资格另行直接检查置信度。
- 目标候选选择由排序改为单次扫描；不增加第二个模型、不增加一帧的推理次数。
- 阈值评估每张图推理一次后缓存。原4阈值比较93次图像推理→36次，减少61.3%，验证指标与旧报告一致。这是PC评估工具效率，不是板端速度提升61.3%。
- 所有修改同时同步两个版本。thermal.json保留D55设置，测温模式仍关闭激光；整鹿检测和人工眼周跟踪是不同模式。

## 实际证据

现有140张照片，92张候选标注进入56训练/19验证/17开发测试。作者分组隔离仍保留。此轮不盲目重训/替换权重，现有标注缺乏人工验收，其他鹿种负样本不足。

本次实际重新评估PC浮点模型：开发测试集confidence=0.65时TP20/FP3/FN12，0.4时TP21/FP4/FN11。降低阈值增加召回也增加误检，因此不是统一降阈值。上述对机器候选框的一致性不是物种识别准确率，也不能代表板端INT8模型。

固定100帧模拟置信度波动（0.9/0.45交替）对照：旧选择器接受40帧、新选择器100帧，60帧为禁止激光的弱延续。这是确定性算法回放，非真实视频的准确率/稳定性报告。

复现：
```sh
python tools/verify.py
python tools/evaluate_detector.py
python tools/benchmark_recognition.py
```

报告：outputs/recognition/threshold_report.json、continuity.json。两个工程的测试不依赖GPU；评估模型需要PC训练环境，不能在MaixCAM2安装PC版Ultralytics后当作NPU部署。

## 参数和回退

config.json新增track_confidence=0.4；confidence=0.65仍是强目标门槛。设置track_confidence等于confidence即关闭弱延续。测温版原模式用config.json，测温云台参数保存在thermal_gimbal.json。修改阈值先用observe核查误检。

新字段对旧配置有默认值，行为变化见ADR0006。模型文件和NPU转换文件本轮未改变，无需重复转换。旧部署包已留副本，恢复旧包即可回退。

## 打印材料

工程output/pdf/milu_A4_print_targets.pdf共6页，建议A4横向、实际大小100%、哑光彩印；无需打印检测框。milu_print_photos目录保留原图及sources.json。全部来自现有开发测试集，未新增进训练集，但已经用于开发评估，因此不作为从未接触的独立测试集。

侧面、头部、卧姿、背面、群体图用于联调不同情况；群体图可能产生多框，原逻辑禁止歧义状态点亮激光，这是预期行为。许可含CC BY-NC，当前按非商业研究使用，保留页脚和来源信息。源图约1024像素，不宣称印刷级300DPI细节。照片按iNaturalist物种元数据选取，部分观测为casual，尚未做专业物种鉴定。

## 还需要补充什么

1. **实拍数据和人工标注**：用实际MaixCAM2拍打印图，在不同距离、侧倾、反光、暗光、运动模糊下采集；按拍摄会话隔离训练/验证。人工补齐所有麋鹿框、纠正候选误框。
2. **混淆负样本**：其他鹿种、牛马、树枝/空白纸/室内背景；不能把“模型没检测到的图”直接认作负样本。未验证物种的照片先复核。
3. **板端性能记录**：镜头FOV、实测推理延迟、光照和目标像素尺寸；先observe确认弱目标数量，再判断是否调帧率/曝光。不要照抄PC速度。
4. **温度实测**：D55的probe、RGB/IR对齐、发射率和参考温度；纸上鹿只能测试视觉跟踪，不能测试真实鹿眼温度。
5. **机械/电气验收**：负载增加后的云台限位/方向、线缆余量、MOS有效电平及关断；这些不能靠阈值优化替代。

只有补齐这些证据后，才适合报告独立实景识别率、进一步重训，并比较板端INT8转换前后的误差。
