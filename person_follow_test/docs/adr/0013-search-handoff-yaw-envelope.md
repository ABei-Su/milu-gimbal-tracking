# ADR0013: Interruptible vision search and independent yaw envelope
User requests detection during initial lift, stop at first valid face, and faster yaw tracking. SEARCH: start vision and wait for first fresh frame (45s timeout/cancellable, before motor enable); during lift poll at every bounded startup step, on strong fresh selected face hold actual measured pose and transition READY. Limit60deg retained. No target at endpoint holds and waits. Weak/stale/future/duplicate detections cannot trigger acquisition. Search callback errors fault/disables; original mechanical home ignores detection. Main tracking uses a separate selector to avoid reusing startup history. No automatic re-lift after target loss.
Independent yaw rate60deg/s, acceleration360deg/s², jerk5000deg/s³ and reference lead8deg; zero-valued overrides preserve old defaults. Pitch parameters unchanged. Derivative envelope and feedback discontinuity use per-axis values consistently. This is command shaping, not motor torque or current tuning. Host tests do not establish achievable loaded speed.
References consulted 2026-10-13: https://github.com/lagadic/visp/blob/master/example/servo-universal-robots/servoUniversalRobotsIBVS.cpp (image-based servo example, GPL; no code copied), https://github.com/pantor/ruckig (per-axis velocity/acceleration/jerk trajectory constraints; MIT; no dependency/code copied). Retain existing small Python trajectory implementation, not claimed equivalent to optimal Ruckig.
