# ADR0016: Restore yaw travel and expose angle saturation
Accepted 2026-10-13. User reports yaw stops while pitch moves.
Latest board log shows yaw goal fixed at -90 from 17:49:46 onwards while pitch changes. Control remains about49Hz and visual about17FPS. This identifies angle saturation, not serial starvation. At measured -89.9 and reference -90 the old limited flag incorrectly reports false.
Use the previously user-confirmed360-degree mechanism range: deployment yaw +/-180 degrees relative to captured tracking origin; pitch remains +/-90. No unlimited turns or automatic origin reset. Settings defaults remain unchanged, accepted yaw maximum expands to180. Protocol and motor direction remain unchanged.
Expose angle_limit_axes from reference with half the0.1-degree protocol resolution tolerance; include in existing once-per-second log. The aggregate limited flag also includes reference saturation. Reversing target can leave the boundary without restarting. Other-axis control remains independent.
Disable the additional40ms request filter in deployment (request_tau=0), retaining the preceding continuous velocity/acceleration/jerk shaper and common two-axis parameters. This removes newly introduced phase lag; it does not prove all mechanical stutter is fixed. Search90 with early-face interruption is unchanged.
Regression tests: cross old yaw boundary while pitch moves; hold both new limits; reverse out; detect command saturation with feedback0.1degree inside. Board validation pending. Rollback yaw_limit=90 and request_tau=.04; old configurations still supported. No vendor PID/current changes.
