# ADR 0008: Faster deployment trajectory
User confirms directions and requests faster smoother tracking. Video 2026-10-12 22.26.07.02 shows approx 17 vision FPS, frame_age .064-.169 s in sampled log and references typically 5-6 degrees/s. Existing lead-braking envelope with 2-degree lead and ramp=18 yields a 5.75 degrees/s request ceiling even before max_rate=12.
Tune deployment only: 40Hz command loop, rate ceiling36, acceleration180, jerk2400, velocity_tau .05, lead5, gain3.2, image smoothing .025. Same continuous substep trajectory and bounded I/O; no new stop guards. Existing defaults remain compatible. New lead envelope is about25.5 degrees/s under ideal fresh feedback; max_rate36 is a ceiling, not promised measured speed. Physical performance and overshoot require board test.
Add measured control frequency, vision FPS/latency and last poll duration to existing once-per-second logs. No model retraining or unverified model swap. Startup relative lift and direction unchanged. Regression uses 17Hz images and 40Hz control; checks response plus derivative bounds and blocked-actuator lead.
